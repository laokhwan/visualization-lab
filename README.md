# Visualization Lab

เว็บแอปการแสดงข้อมูลเพื่อการวิจัย สำหรับนักเรียนชั้นมัธยมศึกษาปีที่ 4 ใช้ภาษาไทยเป็นหลัก พร้อมศัพท์อังกฤษในวงเล็บ ไม่มี backend บัญชีผู้ใช้ หรือระบบส่งคำตอบ

## พื้นที่เรียนรู้

หน้าแรกแสดง Hero เฉพาะก่อนเข้าเรียน พื้นที่เรียนใช้สี่ขั้น **คาดการณ์ → ทดลอง → อธิบาย → คำแนะนำ** พร้อมกราฟหลักและตัวควบคุมที่เกี่ยวข้อง ย้อนขั้นได้โดยไม่ล้างคำตอบหรือ Mastery

ทดลองอิสระใช้กราฟเป็นหลัก ตัวควบคุมแบ่งกลุ่มเปิดปิดได้ และเปิดตัวแก้ข้อมูลแยกจากกราฟ ข้อมูลร่างยังอยู่ขณะสลับโหมด แต่ไม่บันทึกข้ามการโหลดหน้า รายละเอียดโครงสร้างและเกณฑ์ UX อยู่ใน [docs/WORKSPACE-UX.md](docs/WORKSPACE-UX.md)

## รูปแบบการเรียนรู้

- **กิจกรรมตามขั้นตอน (Guided Challenge):** คาดการณ์ → ทดลองเปรียบเทียบกราฟ → อธิบาย → รับคำแนะนำ พร้อมคำถาม 34 ข้อและการฝึกซ้ำจนผ่าน
- **ทดลองอิสระ (Free Exploration):** เปลี่ยนชุดข้อมูล ชนิดกราฟ สี หมวดหมู่ที่เน้น จุดเริ่ม/สิ้นสุดแกน และป้ายค่า พร้อมแก้ข้อมูลเดิม 2–8 แถว และข้อมูลการสังเกตแบบหลายตัวแปรสูงสุด 200 รายการ (หน้าละ 20 รายการ)

กิจกรรม 4 หัวข้อ:

1. เลือกกราฟให้เหมาะสม (Choose the Chart): การเปรียบเทียบหมวดหมู่ แนวโน้ม Scatter Plot, Histogram และ Box Plot
2. การใช้สีในกราฟ (Color Matters): เน้นข้อมูลตามเป้าหมาย สีแยกหมวดหมู่ เรียงลำดับ และสองฝั่งจุดอ้างอิง
3. กราฟที่อาจทำให้เข้าใจผิด (Misleading Charts): แกน ภาพจำลอง 3 มิติ ช่วงชั้น ช่วงเวลา และสองแกนตั้ง
4. ปรับปรุงการนำเสนอข้อมูล (Redesign Challenge): ปรับกราฟเดิม การกระจาย และบริบทสองตัวแปร พร้อมอธิบาย 2 ประเด็น

รักษาชุดข้อมูลเดิมทั้ง 4 ชุด และเพิ่มตัวอย่างกิจกรรมหลังเลิกเรียนสำหรับศึกษาสัดส่วนของผลรวม กราฟจุดใช้แกนนอนเชิงปริมาณเมื่อชุดข้อมูลมีค่าตัวแปร X

รายละเอียดข้อมูล สถิติ การย้ายความคืบหน้า และข้อจำกัดของ Phase 1.3 อยู่ใน [docs/PHASE-1.3.md](docs/PHASE-1.3.md)

## ทดลองในเครื่อง

ติดตั้ง Node.js รุ่น 20 ขึ้นไป แล้วเปิด terminal ในโฟลเดอร์โครงการ:

```sh
npm start
```

เปิด `http://127.0.0.1:4173/visualization-lab/` ไม่ต้องติดตั้งแพ็กเกจสำหรับการเปิดเว็บ ตัว server นี้มีไว้ดูตัวอย่างในเครื่องเท่านั้น ไม่ใช่ backend ของแอป

ต้องเปิดผ่าน HTTP server เพราะใช้ ES modules การดับเบิลคลิก `index.html` ผ่าน `file://` ไม่ใช่วิธีที่รองรับ

## การประเมินและสถานะ

- บันทึกคำคาดการณ์ก่อนเริ่มทดลอง คำคาดการณ์ไม่ถูกให้คะแนน และเมื่อบันทึกแล้วคงไว้สำหรับทบทวน
- ปรับกราฟและกด “บันทึกแบบเปรียบเทียบ” ให้ครบ 2 รูปแบบตามรายการ จึงเปิดคำถามและช่องสะท้อนคิด การโหลดกราฟหรือเปลี่ยนเฉพาะป้ายไม่ถือเป็นหลักฐานใหม่
- มี 17 สถานการณ์ (พื้นฐาน 8 และเพิ่มเติม 9) แล็บเลือกกราฟทั้ง 5 สถานการณ์เป็นพื้นฐาน อีก 3 แล็บมีพื้นฐานแล็บละ 1 สถานการณ์ สถานการณ์ละ 2 ข้อ ผสมคำตอบเดียวและหลายคำตอบ โดยหลายคำตอบต้องเลือกตรงกับชุดคำตอบทั้งหมด
- เพิ่มจำนวนครั้งเมื่อกดส่งคำตอบที่ถูกต้องตามรูปแบบเท่านั้น การเปลี่ยนตัวเลือก การบันทึกกราฟ และการบันทึกกิจกรรมไม่เพิ่มจำนวนครั้งตอบ
- หลังส่งต้องกด “ลองอีกครั้ง” หรือ “ฝึกซ้ำ” ก่อนส่งใหม่ เมื่อตอบผิดมีคำถามชี้นำ โดยไม่ระบุตัวเลือกที่ขาดหรือเปิดเฉลยทันที
- **Mastery:** เคยตอบข้อประเมินถูกต้อง ไม่ลดลงเมื่อตอบผิดระหว่างฝึกซ้ำ และไม่มีการหักคะแนน
- **ทำสถานการณ์ครบ:** เคยผ่านคำถามทั้ง 2 ข้อ มีหลักฐานเปรียบเทียบครบ กราฟปัจจุบันผ่านเกณฑ์ กรอกสะท้อนคิดครบ แล้วกด “บันทึกกิจกรรม”
- สะท้อนคิดตรวจเพียงว่ากรอกแล้ว โดยระบุว่า **ยังไม่ได้ประเมินเหตุผล** ไม่ใช้เพิ่ม Mastery หรืออ้างว่าระบบเข้าใจข้อความ
- การทำครบเก็บสำเนากราฟและข้อความไว้สำหรับทบทวน การทดลองภายหลังไม่แก้หลักฐานเดิม แล็บที่มีหลายสถานการณ์ต้องทำครบทุกสถานการณ์
- แดชบอร์ดสรุปแสดงสถานการณ์พื้นฐานที่ทำครบ แล็บที่ทำพื้นฐานครบ และคำถามที่เคยตอบผ่าน พร้อมการ์ดทั้ง 4 แล็บ สถานะรายสถานการณ์และสิ่งที่ยังต้องทำ กิจกรรมเพิ่มเติมและประวัติรายคำถามเปิดดูแยกได้ มีทางเข้ารายงาน PDF และรักษาผลล่าสุดแยกจาก Mastery
- เปลี่ยนแล็บหรือโหมดแล้วข้อมูลของแต่ละสถานการณ์ยังอยู่ในหน่วยความจำ Free Exploration ไม่มีผลประเมินหรือเกณฑ์บังคับ
- ปุ่มคืนค่ากราฟใน Guided ไม่ลบหลักฐาน ประวัติ Mastery หรือข้อความ ส่วน “เริ่มการฝึกใหม่ทั้งหมด” ต้องยืนยันและล้างเฉพาะ Guided ใน Free ปุ่มคืนค่ากราฟจะคืนชุดข้อมูลปัจจุบันและการตั้งค่ากราฟด้วย
- ข้อมูลที่แก้ใน Free จะนำไปใช้เมื่อกด “นำข้อมูลไปใช้” เท่านั้น ข้อความร่างเก็บในหน่วยความจำระหว่างสลับโหมด การเปลี่ยนชุดข้อมูลหรือคืนตัวอย่างจะถามก่อนทิ้งร่างที่ยังไม่นำไปใช้

## โครงสร้าง

```text
index.html                    โครงหน้าและจุดเริ่มต้น
src/app.js                    เชื่อมเหตุการณ์และอัปเดตหน้าจอ
src/state.js                  สถานะรายโหมดและรายสถานการณ์
src/content/labs.js           เนื้อหา ค่าเริ่มต้น ตัวควบคุม และเกณฑ์
src/content/questions.js      คำถาม ตัวเลือก เฉลย และคำแนะนำรายตัวเลือก
src/content/datasets.js       ชุดข้อมูลพร้อมชนิดตัวแปรและหน่วย
src/content/locales/th.js     คำศัพท์ส่วนติดต่อภาษาไทย
src/charts/                   การตรวจข้อมูล สเกล และ SVG
src/learning/evaluate.js      ตรวจคำตอบและเกณฑ์กราฟแบบ pure function
src/learning/experiments.js   ตรวจและบันทึกหลักฐานเปรียบเทียบ
src/learning/practice.js      ประวัติการส่งคำตอบ Mastery และการทำครบ
src/learning/report.js        สร้าง LearningSummaryV2 ที่ไม่มีตัวตนนักเรียน
src/ui/                       Workspace ตัวควบคุม คำถามรายข้อ และตารางข้อมูล
src/workspace.js              สถานะหน้าจอและการนำทางขั้น แยกจากผลการเรียนรู้
styles/                       สีและตัวอักษร โครงร่าง และองค์ประกอบ
tests/                        การทดสอบตรรกะและเส้นทางใช้งาน
tools/serve.js                server ดูตัวอย่างในเครื่อง
```

ไม่มีขั้นตอน build บนโฮสต์ กิจกรรมใช้ vanilla JavaScript ส่วน PDF โหลด pdfmake และฟอนต์ไทยจาก `vendor/` เมื่อส่งออกเท่านั้น ไฟล์เหล่านี้จัดเตรียมและเก็บไว้ในโครงการแล้ว การเพิ่มภาษาอังกฤษควรย้ายข้อความ UI ที่เหลือไปยัง language resources ก่อนเปิดตัวเลือกภาษา

### เพิ่มเนื้อหา

เพิ่มแล็บใน `labs.js` โดยใช้ `id` ที่ไม่ซ้ำ กำหนด `controls` และ `tasks` แต่ละสถานการณ์ประกอบด้วย `id`, `dataset`, `config`, คำคาดการณ์ คำถาม และ `criteria` ระบบสร้างเมนูและจำนวนกิจกรรมจากรายการนี้อัตโนมัติ

แต่ละสถานการณ์มี `questionIds` อ้างอิงคลังคำถาม และ `experiment` กำหนด 2 รูปแบบด้วย `match` หรือ `design: true` สำหรับรูปแบบที่ผ่านเกณฑ์กราฟ คำถามใช้ `type: 'single' | 'multiple'` พร้อม `correctOptionIds` และทุกตัวเลือกมี `retryFeedback` กับ `explanation` รักษารหัสให้คงที่และเพิ่ม version เมื่อเปลี่ยนเนื้อหา ตรวจความครบด้วย `validateQuestionDefinitions()` และ `npm test`

คู่มือการบันทึกและส่งออกอยู่ใน [docs/PERSISTENCE-AND-PDF.md](docs/PERSISTENCE-AND-PDF.md) รายละเอียดสัญญารายงานและขอบเขต Classroom อยู่ใน [docs/LEARNING-SUMMARY.md](docs/LEARNING-SUMMARY.md)

เพิ่มชุดข้อมูลใน `datasets.js` โดยกำหนด:

- `id`, `title`, `unit`, `xLabel`
- `xType`: `category`, `time` หรือ `number`
- `partToWhole`: ระบุว่าข้อมูลเป็นส่วนประกอบของผลรวมหรือไม่
- `rows`: 2–8 รายการ แต่ละรายการมี `label`, `value` และ `x` สำหรับเวลา/ข้อมูลเชิงปริมาณ

ชุดข้อมูลเวลาต้องเรียงค่า `x` จากน้อยไปมากและไม่ซ้ำกัน ใช้ค่าตัวเลขระหว่าง −1,000,000 ถึง 1,000,000 กราฟวงกลมใช้ค่าที่ไม่ติดลบและมีผลรวมมากกว่าศูนย์

แอปอนุญาตให้ลองกราฟที่ไม่เหมาะกับข้อมูลเพื่อเรียนรู้ พร้อมข้อสังเกตประกอบ แต่ป้องกันการตั้งค่าที่วาดไม่ได้อย่างถูกต้อง เช่น แกนไม่ครอบคลุมข้อมูล

## การทดสอบ

ทดสอบตรรกะโดยไม่ติดตั้งแพ็กเกจ:

```sh
npm test
```

ทดสอบเบราว์เซอร์บน Windows ที่มี Microsoft Edge:

```sh
npm ci
npx playwright install webkit
npm run test:browser
```

ชุดทดสอบประกอบด้วย Edge บนเดสก์ท็อป/จอมือถือ และ WebKit จำลอง iPad แนวตั้ง/แนวนอน เปิดเว็บภายใต้ `/visualization-lab/` บนพอร์ตทดสอบ 4174 แยกจาก preview 4173 เพื่อตรวจเส้นทางไฟล์แบบเดียวกับ project site ภาพหน้าจอคำถามและสรุปอยู่ใน `artifacts/` ผลตรวจไม่ใช่การรับรอง Safari บนอุปกรณ์จริง

หากใช้ Linux หรือ macOS ให้ปรับ project ที่ใช้ `channel: 'msedge'` เป็น Chromium แล้วติดตั้งด้วย `npx playwright install chromium webkit` สำหรับ Linux อาจต้องติดตั้ง system dependencies ตามเอกสาร Playwright

รายการตรวจบนอุปกรณ์จริงก่อนใช้ในชั้นเรียนอยู่ใน `docs/DEVICE-QA.md`

## เผยแพร่บน GitHub Pages

แอปไม่มี build step และใช้เส้นทาง relative จึงรองรับทั้งโดเมนหลักและ project subpath

1. อัปโหลด `index.html`, `styles.css`, โฟลเดอร์ `styles/`, `src/`, **`vendor/`**, **`assets/`** และ `.nojekyll` ไปยัง root ของ repository โดยคงโครงสร้างเดิม ถ้าใช้ GitHub Desktop ให้นำไฟล์โครงการขึ้นตาม `.gitignore`
2. เปิด Settings → Pages → Build and deployment → Deploy from a branch
3. เลือก branch ที่มีไฟล์ เช่น `main` และโฟลเดอร์ `/ (root)` แล้วบันทึก
4. เปิด URL ที่ GitHub แสดง และตรวจว่าหน้าแรก กราฟ CSS และทั้งสองโหมดทำงาน

หากนำทั้งโครงการขึ้น repository ไม่ต้องอัปโหลด `node_modules/`, `artifacts/`, `test-results/` หรือ `playwright-report/` ตาม `.gitignore` และไม่ต้องรัน Node.js บนโฮสต์

การส่งมอบนี้เตรียมไฟล์สำหรับเผยแพร่ แต่ยังไม่ได้สร้าง repository หรือเผยแพร่ไปยังบัญชี GitHub

## ความเป็นส่วนตัวและขอบเขต

- ไม่ใช้ analytics, cookies, sessionStorage หรือระบบส่งข้อมูลไปยัง API
- ค่าเริ่มต้นอยู่ในหน่วยความจำ ผู้เรียนเลือกเปิดบันทึก Guided ได้ โดย IndexedDB เก็บคำตอบ ประวัติ หลักฐานและสะท้อนคิด ส่วน localStorage เก็บเพียงตัวเลือกเปิดบันทึก
- ข้อมูลอยู่เฉพาะเบราว์เซอร์และเส้นทางโครงการนี้ ไม่ซิงก์ข้ามเครื่อง และอาจถูกเบราว์เซอร์ลบ ต้องดูสถานะ “บันทึกแล้ว” เครื่องที่ใช้ร่วมกันอาจเห็นข้อมูลของผู้ใช้ก่อนหน้า
- ไม่มี dashboard ครู การเก็บคะแนนถาวร หรือการตรวจข้อความด้วย AI
- เฉลยและผลอยู่ในเบราว์เซอร์และแก้ไขได้ ผลสรุปไม่ใช่หลักฐานคะแนนที่ป้องกันการดัดแปลง
- ส่งออก PDF ในเครื่องได้ โดยไม่มีชื่อ รหัสนักเรียน หรืออีเมล ผู้เรียนบันทึกลง Files แล้วแนบใน Classroom ด้วยตนเอง ไม่มี OAuth หรือ Classroom API
- การล้างข้อมูลในแอปไม่ลบ PDF ที่ดาวน์โหลดไปแล้ว
- ใช้เฉพาะข้อมูลจำลอง ไม่ป้อนข้อมูลส่วนบุคคลของนักเรียน
