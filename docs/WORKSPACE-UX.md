# พื้นที่เรียนรู้สำหรับ iPad

หน้าแรกแสดง Hero และทางเลือกเริ่มกิจกรรม ทดลองอิสระ หรือเรียนต่อ พร้อมการ์ดเลือกแล็บทั้ง 4 แล็บ ส่วนพื้นที่เรียนแสดงเฉพาะบริบทปัจจุบัน ไม่มี Hero เมนูแล็บและสถานการณ์ใช้ native select ที่มีป้ายกำกับ สถานะการบันทึกอยู่ในส่วนหัว รายละเอียดความเป็นส่วนตัว การเปิดบันทึก และการล้างข้อมูลเปิดจากสถานะนี้ ข้อผิดพลาดเปิดรายละเอียดโดยอัตโนมัติ

## กิจกรรมตามขั้นตอน

1. **คาดการณ์** — อ่านโจทย์และบันทึกก่อนทดลอง คำคาดการณ์ไม่ถูกให้คะแนน หลังบันทึกแล้วเปิดอ่านย้อนหลังได้
2. **ทดลอง** — ปรับกราฟและบันทึกคู่เปรียบเทียบสองรูปแบบตามกติกาเดิม แสดง “กราฟที่ต้องบันทึก” ทั้งสองรูปแบบพร้อมสถานะเหนือปุ่มหลักตลอดเวลา เมื่อบันทึกแล้วกดดูกราฟเดิมจากรายการได้ ปุ่มหลักเปลี่ยนเป็น “ไปอธิบายผล” เมื่อครบ
3. **อธิบาย** — แสดงคำถามทีละข้อ รับคำแนะนำทันทีหลังส่ง ลองใหม่และขอคำใบ้ได้ ตามด้วยสะท้อนคิด การเปลี่ยนข้อหรือขั้นไม่ถือเป็นการส่งคำตอบ
4. **คำแนะนำ** — ทบทวนคำถาม เกณฑ์กราฟ และการกรอกสะท้อนคิด แล้วบันทึกกิจกรรม เมื่อเคยทำครบแล้ว สามารถไปสถานการณ์ถัดไปหรือตรวจเกณฑ์ฉบับปัจจุบันโดยไม่เขียนทับหลักฐานเดิม

ขั้นที่ยังไม่เปิดมีคำอธิบายข้อกำหนด ย้อนขั้นที่เปิดแล้วได้ตลอด แต่ละขั้นรักษาบริบทกราฟของตนเอง ตัวเลือก “กราฟที่แสดง” ใช้กราฟหลักพื้นที่เดียวสำหรับฉบับกำลังปรับ ต้นฉบับ A/B และหลักฐานเมื่อทำครบ การดูหลักฐานปิดตัวควบคุมเพื่อไม่ให้เข้าใจว่าแก้สำเนาที่บันทึกได้ ปุ่มกลับไปปรับเปิดฉบับปัจจุบัน

คำตอบ จำนวนครั้ง Mastery และ completion ใช้ตรรกะเดิม การสะท้อนคิดยังตรวจเพียงการกรอก ไม่ตรวจความหมาย ไม่มีการหัก Mastery จากการลองผิด

## ทดลองอิสระ

กราฟเป็นพื้นที่หลัก กลุ่มตัวแปร สี แกน การกระจาย และป้ายกำกับเปิดปิดได้ แสดงค่าที่ใช้บ่อยด้านหน้า เช่น จำนวนช่วงชั้น แต่ตัวเลือกขั้นสูงเดิมยังอยู่ครบ

ปุ่ม “แก้ข้อมูล” เปิดมุมมองแก้ข้อมูลเฉพาะ กลับกราฟได้ด้วยปุ่มเดียว ร่างที่ยังไม่นำไปใช้เก็บในหน่วยความจำระหว่างสลับมุมมอง โหมด และหน้าแรก หากเปลี่ยนชุดข้อมูลหรือคืนตัวอย่างขณะที่มีร่าง ต้องยืนยันการทิ้งข้อมูลก่อน การกดนำข้อมูลไปใช้ยังเป็นจุดที่เปลี่ยนข้อมูลกราฟจริง

ข้อมูลเดิมใช้ตัวแก้ 2–8 แถว ส่วนข้อมูลการสังเกตใช้หน้าละ 20 รายการ คงขีดจำกัด 200 รายการ ผลต่างจากค่าอ้างอิงยังคำนวณจากตัวแปรต้นทาง ไม่มีคะแนนหรือเงื่อนไขบังคับในโหมดนี้ และไม่มีการบันทึก Free ลง IndexedDB

## รูปแบบหน้าจอและการเข้าถึง

หน้าเว็บใช้ IBM Plex Sans Thai ที่เก็บในโครงการ น้ำหนัก 400 สำหรับเนื้อหา 500 สำหรับปุ่มและป้ายกำกับ และ 600 สำหรับหัวข้อ/ค่าที่เน้น ข้อความใน SVG ใช้ฟอนต์เดียวกับหน้าเว็บ ส่วนรายงาน PDF ยังคง Sarabun ฟอนต์เว็บโหลดจากเส้นทางสัมพัทธ์และไม่เรียกบริการฟอนต์ภายนอก

- iPad แนวนอนและ desktop: กราฟกับแผงขั้นปัจจุบันอยู่ข้างกัน แผงด้านข้างประมาณ 280–350 CSS px
- iPad แนวตั้ง: กราฟเต็มความกว้าง ค่าปรับหลักอยู่ใต้กราฟ และกลุ่มที่พับอยู่เรียงเป็นแถวเมื่อมีพื้นที่
- จอแคบ/Split View: ใช้คอลัมน์เดียว ป้ายเลือกบริบทปรับเป็นหลายแถว
- หน้าเลื่อนแนวตั้งเป็นหลัก ไม่มีแผงเนื้อหาที่บังคับความสูงและเลื่อนซ้อนกัน ตารางกว้างเลื่อนแนวนอนเฉพาะพื้นที่ตารางได้
- ไม่ตรึงกราฟหรือปุ่มไว้ทับคีย์บอร์ด เนื้อหาที่ยาวหรือกราฟแยกช่องสามารถเพิ่มความสูงหน้าได้
- ใช้ native button, select, radio, checkbox, fieldset/legend และ details/summary มีโฟกัสชัด และข้อความสถานะสำหรับโปรแกรมอ่านหน้าจอ
- การปรับค่าปกติอัปเดตกราฟโดยไม่สร้างช่องกรอกใหม่ ส่วนการเปลี่ยนชนิดกราฟ/รูปแบบที่ทำให้ตัวเลือกเปลี่ยนจะสร้างเฉพาะแผงควบคุมและคืนโฟกัส
- SVG รับขนาดพื้นที่จริงผ่าน ResizeObserver โดยคงวิธีคำนวณและโดเมนข้อมูล การส่งออก PDF ยังใช้ขนาดเริ่มต้นแยกจากหน้าจอ

## โครงสร้างและความเข้ากันได้

| โมดูล | หน้าที่ |
|---|---|
| `src/workspace.js` | UI state, การเปิดขั้น และบริบทกราฟรายขั้น |
| `src/ui/workspace.js` | โครง Workspace, step navigation, คำถามรายข้อ, สะท้อนคิด และผลทบทวน |
| `src/ui/control-groups.js` | จัดกลุ่มจากตัวควบคุมเดิมโดยใช้ input เดิม |
| `src/app.js` | เชื่อมเหตุการณ์ การนำทางหน้า โฟกัส ข้อมูลร่าง และขนาดกราฟ |
| `styles/workspace.css` | เลย์เอาต์และส่วนประกอบ Workspace โดยใช้สีเดิม |
| `tests/workspace.test.js` | กติกาการนำทาง ความคงอยู่ของข้อมูล และ SVG ตามขนาด |
| `tests/browser/workspace.spec.js` | เกณฑ์ตำแหน่งองค์ประกอบ การหมุนจอ การย้อนขั้น และร่างข้อมูล |

สถานะหน้าจออยู่ที่ `state.ui` แยกจาก `state.guided` ตัวบันทึกเพิ่มเพียง `lastLocation.step` และ `lastLocation.questionIndex` แบบ optional ตรวจค่าก่อนคืนตำแหน่ง ข้อมูลรุ่นเดิมใช้ได้โดยเลือกขั้นจากความคืบหน้าที่มี และทุกครั้งที่โหลดใหม่เริ่มที่หน้าแรกให้ผู้เรียนเลือกเรียนต่อเอง

คง storage schema 2, IndexedDB database/stores เดิม, contentVersion และ assessment fingerprints เดิม ไม่เพิ่ม backend บัญชี ฐานข้อมูล หรือ runtime dependency การนำทางใช้ fragment ของ URL จึงไม่ต้องตั้งค่า rewrite บน GitHub Pages

หน้าสรุปรวมยอดพื้นฐาน/เพิ่มเติม และเปิดรายละเอียดแล็บ/สถานการณ์ได้ หน้ารายงาน PDF แยกจากรายการผล แต่ใช้ LearningSummaryV2/LearningReportV2 เดิม ฟอนต์และ PDF engine มาจากไฟล์ในโครงการ ผลฝั่งเบราว์เซอร์แก้ไขได้ ไม่ใช่ผลการเรียนที่ผ่านการยืนยัน สะท้อนคิดไม่ได้รับการประเมินเหตุผล

## ตรวจรับ

รัน `npm test` และ `npm run test:browser` ชุดเบราว์เซอร์ใช้ project subpath และทดสอบ Edge, จอมือถือ และ WebKit จำลอง iPad ทั้งสองแนว ครอบคลุมทั้ง 17 สถานการณ์ การนับครั้ง คำใบ้ Mastery ข้อมูลเสีย การย้ายข้อมูลเก่า สถานะบันทึกหลายแท็บ และ PDF

เกณฑ์ UX เพิ่มเติมตรวจว่าหน้าแรกแยกจากกิจกรรม ขั้นที่ยังไม่เปิดข้ามไม่ได้ ในฮิสโทแกรมปกติบน iPad กราฟ ค่าปรับหลัก และปุ่มบันทึกอยู่ใน viewport เดียวกัน ไม่มีการเลื่อนแนวตั้งซ้อน และการหมุนจอ/ย้อนขั้นไม่ล้างข้อความหรือเพิ่มจำนวนครั้ง

ภาพตัวอย่างจาก browser tests อยู่ใน `artifacts/*-workspace.png` ยังต้องตรวจ Safari, คีย์บอร์ดไทย, Files/Share และ VoiceOver บน iPad จริงก่อนใช้ในชั้นเรียนตาม `docs/DEVICE-QA.md`

ผลตรวจวันที่ 4 พฤศจิกายน 2569: unit tests ผ่าน 55/55 รายการ และ browser tests ผ่าน 124/124 รายการในรอบเต็มเดียว บน Edge, จอมือถือ และ WebKit จำลอง iPad แนวตั้ง/แนวนอน ตรวจ PDF ตัวอย่างรวม 67 หน้า และรายงานจาก iPad จำลองทั้งสองแนว (รายงานพื้นฐาน 10 หน้าและรายงานเพิ่มเติม 19 หน้าต่อแนว) โดยตรวจข้อความไทย คำเตือน และขอบเขตข้อความ พร้อมตรวจภาพหน้าตัวอย่างด้วยตา ผลนี้ยังไม่ครอบคลุมการใช้อุปกรณ์ iPad จริง
