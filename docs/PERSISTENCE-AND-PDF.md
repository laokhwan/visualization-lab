# Phase 1.1–1.2: การบันทึก คำใบ้ และรายงาน PDF

## สำหรับผู้เรียน

1. ถ้าเป็นเครื่องส่วนตัวหรือได้รับอนุญาตให้บันทึก ให้เลือก **เปิดบันทึกบนเครื่องนี้** ก่อนปิดหน้า ตรวจสถานะ **บันทึกแล้ว**
2. เมื่อกลับมาเปิดเว็บ ระบบกู้คืน Guided ก่อนแสดงกิจกรรม ตรวจว่าเป็นการฝึกของตนก่อนเรียนต่อ โดยเฉพาะ iPad ที่ใช้ร่วมกัน
3. คำตอบผิดไม่หัก Mastery คำใบ้มี 3 ระดับ และกดดูเพิ่มเติมได้โดยไม่เพิ่มจำนวนครั้งตอบ ระดับสูงสุดเป็นขั้นทดลอง ไม่ใช่ชุดเฉลย
4. เปิด **สรุปการเรียนรู้ → รายงานสำหรับส่งงาน** ค่าเริ่มต้นรวมหลักฐานที่บันทึกแล้ว เลือกรวมข้อความร่างได้ต่างหาก
5. กด **สร้าง PDF** รอไฟล์พร้อม แล้วกด **บันทึก PDF** หรือ **แชร์ไฟล์** ถ้าไม่มีตัวเลือกแชร์ ให้เปิด PDF เพื่อดูหรือพิมพ์ บน iPad บันทึกลง Files แล้วแนบงานใน Classroom ด้วยตนเอง
6. ก่อนคืนเครื่องร่วมกัน ใช้ **ปิดบันทึกและลบข้อมูลจากเครื่อง** หลังยืนยัน แอปยังใช้ข้อมูลปัจจุบันในหน่วยความจำต่อได้จนปิดหรือโหลดใหม่

ไม่มีชื่อ รหัสนักเรียน อีเมล บัญชีผู้ใช้ หรือการส่งข้อมูลออกจากแอปอัตโนมัติ ข้อความสะท้อนคิดเป็นข้อมูลที่ผู้เรียนกรอกเอง จึงไม่ควรใส่ข้อมูลส่วนบุคคล

## การคืนค่าและความขัดข้อง

- คืนค่ากราฟไม่ลบประวัติ Mastery หรือหลักฐานเดิม
- เริ่มการฝึกใหม่ทั้งหมดต้องยืนยัน และล้าง Guided ที่บันทึกด้วย โดยไม่เปลี่ยน Free Exploration
- หากพื้นที่เต็มหรือบันทึกไม่ได้ ให้เรียนต่อในหน้านี้ได้ แต่ข้อมูลใหม่อาจหายเมื่อปิดหน้า ใช้ **ลองบันทึกอีกครั้ง** เมื่อแก้ปัญหาแล้ว โดยไม่ต้องส่งคำตอบใหม่
- เปิดหลายแท็บอาจเกิด revision conflict แท็บเก่าจะหยุดเขียนและให้โหลดข้อมูลล่าสุด ไม่รวมประวัติแบบอัตโนมัติ
- ข้อมูลเสียหรือเกณฑ์เปลี่ยนจะไม่ถูกเขียนทับทันที ส่วนที่กู้คืนได้ยังใช้ต่อได้ การเริ่มเฉพาะส่วนที่มีปัญหาต้องยืนยันก่อน
- รุ่น schema ที่ไม่รองรับจะหยุดการเขียน ไม่พยายามย้ายข้อมูลแบบเดา รุ่นบันทึกแรกคือ 1 ยังไม่มี schema เก่าที่ต้อง migration
- ปิดการบันทึกไม่ลบไฟล์ PDF ที่อยู่ใน Files, Downloads หรือ Classroom

ข้อมูลเป็นแบบ best-effort ตามข้อจำกัดของเบราว์เซอร์ ไม่ใช่ระบบสำรองข้อมูล ไม่รับประกันการอยู่ถาวร การย้าย URL/repository หรือเปลี่ยนเบราว์เซอร์จะไม่ได้ความคืบหน้าเดิมโดยอัตโนมัติ การเก็บความคืบหน้าไม่ทำให้แอปทั้งหมดใช้งานออฟไลน์ได้

## โครงสร้างสำหรับผู้พัฒนา

- `src/storage/schema.js`: แปลงและตรวจ state, manifest, assessment fingerprint และ task recovery
- `src/storage/database.js`: IndexedDB transaction, append-only attempt records และ compare-and-swap revision
- `src/storage/controller.js`: opt-in, write queue, debounce, status, reset, recovery และการปิดบันทึก
- `src/content/hints.js`, `src/learning/feedback.js`: ข้อความ 3 ระดับและการเลือกจาก streak ของคำตอบผิด
- `src/report/model.js`: `LearningReportV2` ที่แยกจาก `LearningSummaryV2`
- `src/report/pdf.js`, `src/report/controller.js`: document definition, local engine, Blob/download/share และการคืน object URL

IndexedDB มี stores `meta`, `tasks`, `attempts` หลักฐานและข้อความอยู่ใน task records ประวัติเก็บแยกตาม task/question/attemptNumber จึงไม่เขียนประวัติทั้งหมดใหม่ทุกครั้งที่พิมพ์ ไม่มี bitmap หรือ PDF Blob ใน storage

การกู้คืนสร้าง state ที่รู้จักใหม่ ตรวจ IDs, selections, text limits, graph config, dataset snapshots, attempt references และ completion checkpoints แล้ว replay ประวัติด้วยตัวประเมินปัจจุบัน ไม่เชื่อ mastery/count/correct flags ที่บันทึกมา การตรวจเหล่านี้เป็นการตรวจความสอดคล้อง ไม่ใช่การป้องกันผลปลอม

`storageSchemaVersion` เป็น 2 (อ่านและย้าย V1 ได้) ส่วน `contentVersion` เป็นรุ่นเนื้อหาที่แสดงในรายงาน `assessmentManifest` แยกแต่ละ task โดยมี version และ fingerprint ของคำถาม ข้อมูล เกณฑ์ และรูปแบบทดลอง เปลี่ยน UI หรือคำใบ้โดยไม่เปลี่ยนส่วนประเมินจะไม่ลบ Mastery เมื่อเปลี่ยนตรรกะที่อยู่นอกนิยามข้อมูล ให้เพิ่ม assessment engine/task version ใน schema module ด้วย

การส่งคำตอบหรือบันทึกหลักฐานจะเข้าคิวทันที ข้อความร่างหน่วง 500 มิลลิวินาทีและ flush เมื่อออกจากช่อง/เปลี่ยนโหมดหรือซ่อนหน้า สถานะ saved แสดงหลัง transaction ของข้อมูลล่าสุด complete และไม่มีข้อความร่าง/งานใหม่รออยู่เท่านั้น การปิดแอปก่อน transaction จบยังอาจทำให้ข้อมูลล่าสุดไม่ถูกบันทึก

## การจัดเตรียม PDF

ไฟล์ที่ใช้จริงถูกเก็บใน `vendor/` และฟอนต์ต้นฉบับพร้อม SIL Open Font License อยู่ใน `assets/fonts/` ไม่เรียก CDN หรือบริการ PDF ภายนอก

เมื่อเปลี่ยนเวอร์ชัน pdfmake หรือฟอนต์:

```sh
npm ci
npm run prepare:pdf
```

Commit ไฟล์ `vendor/`, `assets/`, `package.json` และ `package-lock.json` ที่เกี่ยวข้อง GitHub Pages ไม่ต้องรันคำสั่งนี้เอง

สร้างรายงานตัวอย่างสำหรับ QA:

```sh
node tools/check-pdf.mjs
```

ผลอยู่ใน `artifacts/sample-report.pdf` ใช้ข้อมูลจำลองครบทุกแล็บและข้อความยาว ควรตรวจทุกหน้าด้วย PDF renderer เช่น PyMuPDF/Poppler พร้อมตรวจฟอนต์ สระ วรรณยุกต์ กราฟ หัวตาราง และคำเตือน ไม่ใช้แค่จำนวน bytes เป็นเกณฑ์ผ่าน

## ข้อจำกัดของรายงาน

- รายงานแยกผลตรวจอัตโนมัติจากสะท้อนคิดที่ยังไม่ได้ประเมินเหตุผล
- กราฟเมื่อทำครบและสะท้อนคิดที่บันทึกแล้วเป็นหลักฐานเดิม ฉบับร่างที่รวมเพิ่มมีป้ายกำกับ
- ตัวเลือกคำตอบและเฉลยไม่ถูกรวมในรายงาน Free Exploration ไม่ถูกรวมเช่นกัน
- PDF เป็น snapshot ณ เวลาสร้าง ไม่เปลี่ยนตามการฝึกภายหลัง ต้องสร้างใหม่เมื่อต้องการข้อมูลล่าสุด
- ทุกหน้าระบุว่าผลจากเบราว์เซอร์แก้ไขได้และไม่ใช่ผลการเรียนที่ยืนยันแล้ว ไม่มี digital signature หรือการส่งคะแนน
- PDF มีข้อความและกราฟเวกเตอร์ แต่ยังไม่ได้รับรองมาตรฐาน PDF/UA ใช้หน้าสรุป HTML และตารางเป็นทางเลือกที่เข้าถึงได้

## การขยายเนื้อหา Phase 1.3

- รุ่น payload ปัจจุบัน `storageSchemaVersion: 2` และเนื้อหา `practice-1.3`; IndexedDB ยังคงใช้ database version 1 กับ stores เดิม ไม่สร้างฐานข้อมูลเพิ่ม
- รับ payload V1 ผ่านการย้ายแบบเพิ่มกิจกรรม รักษา fingerprint ของ 5 สถานการณ์เดิม จากนั้นเขียน V2 ในการบันทึกครั้งถัดไป ไม่เขียนทับข้อมูลรุ่นที่ไม่รู้จัก
- กิจกรรมเพิ่มเติมที่ไม่มีใน V1 เริ่มว่าง ไม่ถือเป็นข้อมูลเสีย ทดสอบด้วย `tests/fixtures/progress-v1.json` ที่เก็บจากโค้ดรุ่นก่อน
- เกณฑ์ที่เปลี่ยนยังแยกกักเป็นรายสถานการณ์และรอการยืนยัน การเปลี่ยนวิธีคำนวณต้องเปลี่ยน `calculationVersion` เพื่อเปลี่ยน fingerprint ของเนื้อหาใหม่
- หน้าสรุปแยกพื้นฐานและเพิ่มเติม การเพิ่มบทเรียนไม่ลบ Mastery เดิม
- PDF เลือกหลักฐานทุกแล็บหรือเฉพาะแล็บได้ ผลรายข้อยังรวมทั้งหมด และไฟล์ใช้กติกาสถิติเดียวกับหน้าจอ
- รุ่นก่อนหน้าไม่สามารถอ่าน V2 ได้ ควรใช้เว็บรุ่นปัจจุบันต่อหลังย้ายข้อมูล ไม่ลดรุ่นเว็บระหว่างเรียน

## Workspace

หน้าแรกกับพื้นที่เรียนแยกกัน โหลดใหม่แล้วเลือกเรียนต่อเพื่อเข้ากิจกรรม สถานะบันทึกอยู่ในส่วนหัว กดเพื่อเปิดรายละเอียดหรือเปิด/ปิดการบันทึก หากมีข้อผิดพลาด รายละเอียดจะเปิดให้เห็นอัตโนมัติ

`lastLocation` เพิ่ม `step` และ `questionIndex` แบบ optional เท่านั้น ไม่เปลี่ยน schema 2 หรือ assessment fingerprints ข้อมูลเก่าที่ไม่มีตำแหน่งขั้นใช้ขั้นที่เหมาะกับความคืบหน้าที่กู้คืนได้ UI state ส่วนอื่นอยู่ในหน่วยความจำ และข้อมูลร่าง Free ไม่เข้า storage

เข้ารายงานผ่าน สรุป → รายงานสำหรับส่งงาน (PDF) กราฟในรายงานใช้ขนาดส่งออกเดิม ไม่ขึ้นกับการหมุนหน้าจอหรือแผงตัวควบคุมที่เปิดอยู่
