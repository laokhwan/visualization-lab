# Phase 1.3: การแสดงข้อมูลเพื่อการวิจัย

คงกิจกรรมพื้นฐาน 5 สถานการณ์และเพิ่ม 12 สถานการณ์ รวม 17 สถานการณ์/34 คำถาม การฝึกไม่หัก Mastery จากคำตอบผิด คำคาดการณ์ไม่ถูกให้คะแนน และสะท้อนคิดตรวจเพียงการกรอก ไม่มี AI ประเมินข้อความ

## เนื้อหาและข้อมูล

| แล็บ | สถานการณ์เพิ่มเติม | วัตถุประสงค์ |
|---|---|---|
| เลือกกราฟ | `scatter-relationship`, `histogram-distribution`, `boxplot-groups` | ความสัมพันธ์ การกระจาย และการเปรียบเทียบกลุ่ม |
| สี | `categorical-colors`, `sequential-colors`, `diverging-reference` | เลือกหน้าที่ของสีตามชนิดตัวแปรและจุดอ้างอิง |
| กราฟที่อาจทำให้เข้าใจผิด | `perspective-3d`, `binning-context`, `time-window`, `dual-axis` | ตรวจมุมมอง การจัดกลุ่ม บริบทเวลา และสเกลแยกกัน |
| ปรับปรุงกราฟ | `redesign-distribution`, `redesign-time-context` | ใช้หลักการร่วมกัน ยอมรับมากกว่าหนึ่งรูปแบบที่อธิบายได้ |

ชุดข้อมูลใหม่ทั้งหมดเป็น **ข้อมูลจำลอง** ไม่ใช่ผลวิจัยจริง และไม่ยืนยันเหตุและผล:

- `shade`: สัดส่วนร่มเงา (%) กับอุณหภูมิพื้นผิว (°C) มีค่า X ซ้ำที่ใช้ได้จริงในเชิงโครงสร้าง
- `soil`: เวลาให้น้ำซึม (นาที) ของกลุ่มไม่มีพืชและมีพืช กลุ่มละ 12 ค่า เก็บค่า 24 ไว้อภิปรายค่านอกเกณฑ์
- `environment`: ผลต่างคำนวณจากอุณหภูมิลบค่าฐานใหม่เมื่อแก้ข้อมูลต้นทางและไม่ให้แก้ผลต่างอิสระ ชุดนี้มีอุณหภูมิ พื้นที่ ประเภทพื้นผิว และผลต่างจาก 30°C ซึ่งเป็นค่าอ้างอิงในบทเรียน **ไม่ใช่เกณฑ์ความปลอดภัย**
- `researchTime`: อุณหภูมิ 24 วัน ภาพรวมเพิ่มขึ้น แต่วันที่ 22–24 ลดลง
- `dualResearch`: อุณหภูมิ (°C) และความชื้นดิน (%) 12 วัน สำหรับทดลองสองแกน แยกช่อง และดัชนี

## โครงสร้างโมดูล

| ไฟล์ | หน้าที่ |
|---|---|
| `src/content/expansion.js` | กิจกรรม คำถาม คำแนะนำรายตัวเลือก และคำใบ้สามระดับของส่วนเพิ่มเติม |
| `src/content/research-data.js` | Dataset V2 และ metadata ของข้อมูลจำลอง |
| `src/data/view.js` | แปลงหน่วยสังเกตเป็นมุมมองสำหรับกราฟ โดยรักษาข้อมูลดิบ |
| `src/data/config.js` | อ่าน/ตั้งค่าการเข้ารหัสแบบซ้อนและเปรียบเทียบการตั้งค่า |
| `src/statistics/distribution.js` | ฟังก์ชันบริสุทธิ์สำหรับช่วงชั้น ควอร์ไทล์ และ Box Plot |
| `src/charts/research-validation.js` | ตรวจข้อมูล ชนิดกราฟ สี และช่วงแกนก่อนวาด |
| `src/charts/research.js` | SVG สถิติ คำอธิบายสี และบริบทที่ใช้ร่วมกับ PDF |
| `src/learning/design-rules.js` | ตรวจหน้าที่การออกแบบ ไม่บังคับชื่อชุดสีเฉพาะ |
| `src/ui/research.js` | ตัวควบคุม ตาราง และตัวแก้ข้อมูลหน้าละ 20 รายการ |
| `src/storage/schema.js` | ย้าย V1 → V2 และตรวจ/replay ผลรายสถานการณ์ |

Dataset V2 ใช้ `{schemaVersion:2, id, title, recordLevel, provenance, fields, records, encoding}` แต่ละ field มี `id`, `label`, `type` (`nominal`, `quantitative`, `time`) และหน่วยเมื่อเป็นตัวเลข/เวลา แต่ละ record มีรหัสภายในที่ไม่ซ้ำ ไม่ใช่รหัสนักเรียน โครงสร้าง `rows` ของข้อมูลเดิมยังคงเดิม; renderer ใหม่อ่าน `records` ผ่าน adapter เท่านั้น

รับข้อมูลใหม่ 1–200 รายการ ตัวเลขจำกัด ±1,000,000 ค่า `null` หรือช่องว่างหมายถึงขาดข้อมูล และตัดเฉพาะหน่วยที่ไม่มีตัวแปรจำเป็นต่อกราฟนั้น พร้อมแจ้งจำนวน ไม่แปลงช่องว่างเป็นศูนย์ ตัวเลขผิดรูปแบบ/ไม่สิ้นสุดถูกปฏิเสธ ค่า X ซ้ำใช้กับ Scatter ได้ แต่เส้นต้องมี X เรียงและไม่ซ้ำ จุดที่ซ้อนกันยังนับเป็นหลายหน่วยสังเกต ไม่มี jitter หรือเส้นเชื่อมแฝง จำกัด Box Plot เปรียบเทียบไม่เกิน 8 กลุ่มต่อภาพเพื่อให้อ่านได้

## วิธีคำนวณและความหมาย

- ควอร์ไทล์ **R type 7**: เรียงค่า ใช้ตำแหน่ง `(n − 1)p` ในดัชนีเริ่ม 0 แล้วแทรกเชิงเส้นระหว่างค่าข้างเคียง
- `IQR = Q3 − Q1`; ขอบเขต `Q1 − 1.5 IQR` ถึง `Q3 + 1.5 IQR` รวมค่าที่ตรงขอบ หนวดสิ้นสุดที่ค่าจริงภายในขอบเขต ค่าภายนอกแสดงแยกโดยไม่ลบทิ้ง
- ชุดว่างไม่มีค่าสรุป ค่าเดียว/ค่าซ้ำทั้งหมดให้ IQR=0 ไม่เกิด NaN หรือหารศูนย์
- Histogram รวมขอบซ้าย ไม่รวมขอบขวา ยกเว้นช่วงสุดท้ายรวมขอบขวา จำกัด 20 ช่วง ต้องครอบคลุมค่าทั้งหมด เมื่อกำหนดความกว้าง จุดเริ่มเป็นพหุคูณของความกว้างที่ไม่เกินค่าต่ำสุด
- ช่วงกว้างไม่เท่ากันใช้ **ความหนาแน่นความถี่** `count / width` อัตโนมัติ ทำให้พื้นที่แท่งแทนจำนวน หน่วยความสูงเป็นความถี่ต่อหน่วยของแกนนอน ไม่ใช่ probability density
- หลักฐานสอง Histogram ต้องมีขอบช่วงที่แสดงจริงต่างกัน การเปลี่ยนป้าย พารามิเตอร์ที่ไม่ได้ใช้ หรือสลับ count/density เพียงอย่างเดียวไม่ปลดล็อก
- สีตรวจตามชนิดตัวแปรและวัตถุประสงค์ ยอมรับหลาย palette มีชื่อ/หน่วยประกอบ และโหมดขาวดำสำหรับตรวจการอ่าน ไม่อ้างว่าเป็นการรับรองความเหมาะสมกับความบกพร่องการเห็นสีทุกแบบ
- Diverging รวมจุดอ้างอิงไว้ในโดเมนแม้ข้อมูลอยู่ฝั่งเดียว 0 ของผลต่างหมายถึงไม่ต่างจากค่าฐาน 30°C
- ภาพ 3 มิติเป็น SVG ประกอบจำลอง ไม่ใช่ตัวแปรหรือแบบจำลองสถิติที่เพิ่มขึ้น การเลือกช่วงเวลาไม่ได้ผิดเสมอ แต่ต้องเปิดเผยช่วงที่แสดงและบริบทเต็ม
- สองแกนใช้สเกลแยกกัน จุดตัดไม่ได้แปลว่าค่าทางกายภาพเท่ากัน ทางเลือกคือแยกช่องหรือดัชนี `ค่า / ค่าแรก × 100` โดยระบุวันและค่าฐาน ห้ามฐานเป็นศูนย์

## ความคืบหน้าและรายงาน

Snapshot และ completion ใช้ deep copy เพื่อไม่ให้ค่าซ้อนของ bins, encoding หรือสีเปลี่ยนหลักฐานย้อนหลัง เก็บ `calculationVersion` ในหลักฐานเพิ่มเติม คงรหัสและ fingerprint ของเนื้อหาพื้นฐานเดิม

`storageSchemaVersion:2` อ่าน payload V1 ที่รู้จักได้โดยเริ่มกิจกรรมใหม่ว่าง ใช้ IndexedDB/stores เดิมและคงการเลือกเปิดบันทึกก่อน การตรวจข้อมูลยัง replay คำตอบ ไม่เชื่อ mastery/correctness ที่บันทึกมาโดยตรง รุ่นที่ไม่รู้จักหรือส่วนเสียไม่ถูกเขียนทับโดยเงียบ

`LearningSummaryV2` แยกยอดพื้นฐานและเพิ่มเติม `LearningReportV2` เพิ่มข้อมูลวิธีคำนวณ สถิติ หน่วย สี บริบท และภาพจำลอง เลือกหลักฐานทุกแล็บหรือแล็บเดียวได้ โดยผลอัตโนมัติรายข้อยังรวมทั้งหมด ตัวเลือกนี้ไม่เปลี่ยนความคืบหน้า PDF ใช้ข้อมูลและ renderer เดียวกับหน้าจอ สร้างด้วย pdfmake/ฟอนต์ในโครงการโดยไม่ใช้บริการภายนอก

**ผลฝั่งเบราว์เซอร์แก้ไขได้ ไม่ใช่ผลการเรียนที่ผ่านการยืนยัน** ไม่มี backend ระบบบัญชี การเก็บตัวตน หรือ Google Classroom API ผู้เรียนแนบไฟล์เอง การล้างแอปไม่ลบ PDF ที่บันทึกแล้ว

## การตรวจรับ

`npm test` ตรวจสถิติ การจับคู่กราฟ/ตัวแปร/สี คำถาม การนับครั้ง Mastery หลักฐาน migration จาก golden V1 และรายงาน V2 `npm run test:browser` ตรวจครบทุกสถานการณ์เดิม/ใหม่ การ reload ข้อมูลเสีย opt-in การแยก Free และ PDF บน Edge/มือถือ/WebKit จำลอง iPad แนวตั้งและแนวนอน ภายใต้ project subpath

`node tools/check-pdf.mjs` สร้างรายงานเต็มทุกกิจกรรมพร้อมข้อความยาวสำหรับ QA; `python tools/verify-pdf.py artifacts/sample-report.pdf` ตรวจ Unicode/ขอบข้อความ/คำเตือนและ render ทุกหน้า ต้องเปิดตรวจภาพกราฟและการจัดหน้าประกอบ ผลทดสอบจำลองไม่แทนการตรวจ Safari, Files, การแชร์ และ VoiceOver บน iPad จริงตาม `DEVICE-QA.md` PDF ยังไม่ได้รับรอง PDF/UA

ผลตรวจรอบส่งมอบ 3 พฤศจิกายน 2026:

- Unit tests ผ่าน 49 รายการ
- Browser regression รอบหลักผ่าน 92 กรณี และกรณีเพิ่มเติมเรื่องค่าซ่อนที่ผิดรูปแบบ/ผลต่างคำนวณผ่านอีก 4 กรณี รวม 96 กรณีบนทั้งสี่ browser projects
- รายงานทุกกิจกรรมพร้อมข้อความยาว 67 หน้า และ PDF จาก WebKit iPad ทั้งสองแนวแบบเลือกหลักฐานแล็บ 19 หน้า ผ่านการตรวจข้อความ/ขอบหน้า/คำเตือนและ render ทุกหน้า เปิดตรวจภาพตัวอย่างกราฟใหม่ประกอบแล้ว
- พบและแก้สถานะ saved ที่แสดงเร็วเกินไปเมื่อมีคิวบันทึกใหม่ พร้อม unit/browser regression ไม่ให้โหลดใหม่หลังเห็นสถานะ saved แล้วสูญเสีย completion ล่าสุด
- ยังต้องตรวจบนอุปกรณ์จริงตามรายการ DEVICE-QA ก่อนใช้ในชั้นเรียน
